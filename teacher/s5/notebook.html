Learning goals

By the end of Session 5 a student can:

  1. Choose between Box, Rc, RefCell, Arc and Mutex from three questions: how many owners, how many threads, does anyone change it.
  2. Start threads with move closures, join them, and use their results.
  3. Pass results through mpsc channels, and explain why a receiver loop can hang.
  4. Share changing state with Arc<Mutex<T>>, keeping locks short.
  5. Read an E0277 about Send and fix it.
  6. Split work with thread::scope.
  7. Write async code with tokio's join! and spawn, and say when async beats threads.
  8. Write unit and integration tests, and read and write JSON with serde.

Deeper notes by topic

Smart pointers

Frame every pointer as an answer to an ownership question students already understand. Box is ownership with the value on the heap. Rc relaxes "one owner". RefCell relaxes "checked at compile time". Don't go deep on Weak, Cell or Deref; mention Weak only if someone asks about cycles (a parent and child holding Rcs to each other never free).

Threads

Run the thread_spawn slide twice so the room sees the order change. That single observation explains most of the homework design: the report sorts by name and leaves out who cleaned which tile. main returning ends the process, unfinished threads included; that's why we join.

Channels versus shared state

Teach channels first. They need no locks, and send moving the value is ownership doing the safety work. Shared state with Arc<Mutex> is for when the threads really must see one changing thing. Rust prevents data races at compile time; it does not prevent deadlocks or race conditions in logic (which bot got the last unit of dirt). Make that distinction explicit, because "fearless" can be oversold.

Send and Sync

Students only need to read the error, not implement the traits. The first line of the E0277 says "cannot be sent between threads safely". Auto traits: a struct is Send when all its fields are. unsafe impl Send exists and comes back in Session 6 as an example of what unsafe promises.

Async

Twenty minutes is enough for the model, not the details. The three things that matter: futures are lazy (like Session 4's iterators), a runtime is needed and tokio is the default, and blocking calls inside async code stall everything on that worker. Skip Pin, select! and async traits. The final project's async stretch goal is optional.

Testing and serde

Students have run tests for four sessions; today they write them. Push for test names that state rules. Homework 5 is the first assignment that grades the student's own tests. For serde, show the missing-field error: it's the moment people see why typed deserialization beats picking fields out of a map.

Lab solution: Swarm Mode

The full file is teacher/s5/lab5-solution-lib.rs; drop it in as labs/lab5-swarm-mode/src/lib.rs and all nine tests pass, with clippy and fmt clean.

//! Lab 5: Swarm Mode. Teacher's solution.
use std::sync::mpsc;
use std::sync::{Arc, Mutex};
use std::thread;

/// How much dust is in a room. Pretend it takes a scanner a while.
/// Given to you: it's the same answer every time for the same room.
pub fn dust_in(room: &str) -> u32 {
    room.bytes().map(u32::from).sum::<u32>() % 50 + room.len() as u32
}

/// Step 1. One thread per room, each running `dust_in`. Returns the readings
/// in the same order as `rooms`, whichever thread finishes first.
pub fn scan_rooms(rooms: Vec<String>) -> Vec<u32> {
    let handles: Vec<_> = rooms
        .into_iter()
        .map(|room| thread::spawn(move || dust_in(&room)))
        .collect();
    handles.into_iter().map(|h| h.join().unwrap()).collect()
}

/// Step 2. One thread per room again, but each one sends its reading down a
/// channel, and the caller adds up whatever arrives.
pub fn total_dust(rooms: Vec<String>) -> u32 {
    let (tx, rx) = mpsc::channel();
    for room in rooms {
        let tx = tx.clone();
        thread::spawn(move || tx.send(dust_in(&room)).unwrap());
    }
    drop(tx);
    rx.iter().sum()
}

/// Step 3. `bots` threads share one squeak counter. Each bot takes
/// `steps_each` steps and squeaks on every second step (steps 2, 4, 6...).
/// Returns the final count.
pub fn count_squeaks(bots: usize, steps_each: u32) -> u32 {
    let squeaks = Arc::new(Mutex::new(0));
    let mut handles = Vec::new();
    for _ in 0..bots {
        let squeaks = Arc::clone(&squeaks);
        handles.push(thread::spawn(move || {
            for step in 1..=steps_each {
                if step % 2 == 0 {
                    *squeaks.lock().unwrap() += 1;
                }
            }
        }));
    }
    for h in handles {
        h.join().unwrap();
    }
    *squeaks.lock().unwrap()
}

/// Step 4. Split `readings` into `parts` chunks, add each chunk on its own
/// scoped thread, and return the grand total. `parts` of 0 counts as 1.
pub fn scoped_sum(readings: &[u32], parts: usize) -> u32 {
    let size = readings.len().div_ceil(parts.max(1)).max(1);
    thread::scope(|s| {
        let handles: Vec<_> = readings
            .chunks(size)
            .map(|chunk| s.spawn(move || chunk.iter().sum::<u32>()))
            .collect();
        handles.into_iter().map(|h| h.join().unwrap()).sum()
    })
}

/// One cleaning job for the swarm.
#[derive(Debug, Clone, PartialEq)]
pub struct Job {
    pub id: u32,
    pub room: String,
}

/// Step 5. A worker pool. Start `workers` threads (0 counts as 1) that share
/// one job queue. Each worker takes jobs until the queue is empty and reports
/// `(id, "room: dust")` for each. Returns every report, sorted by id.
pub fn run_jobs(jobs: Vec<Job>, workers: usize) -> Vec<(u32, String)> {
    let (job_tx, job_rx) = mpsc::channel::<Job>();
    let job_rx = Arc::new(Mutex::new(job_rx));
    let (done_tx, done_rx) = mpsc::channel();

    let mut handles = Vec::new();
    for _ in 0..workers.max(1) {
        let job_rx = Arc::clone(&job_rx);
        let done_tx = done_tx.clone();
        handles.push(thread::spawn(move || {
            loop {
                let next = job_rx.lock().unwrap().recv();
                let Ok(job) = next else { break };
                let report = format!("{}: {}", job.room, dust_in(&job.room));
                done_tx.send((job.id, report)).unwrap();
            }
        }));
    }
    drop(done_tx);

    for job in jobs {
        job_tx.send(job).unwrap();
    }
    drop(job_tx);

    let mut reports: Vec<(u32, String)> = done_rx.iter().collect();
    for h in handles {
        h.join().unwrap();
    }
    reports.sort();
    reports
}

Praise: collecting handles before joining; drop(tx) with a comment saying why; the job taken in its own let in step 5 so the lock is released before the work. Redirect: Arc in step 4 (scoped threads can borrow), and sorting step 1's results (the order is the join order, so no sort is needed).

Homework 5 solution and grading

Reference files are in teacher/s5/hw5-solution/: copy config.rs, sim.rs and lib.rs into a student's src/ to check the tests.

impl Config {
    /// Read a config from JSON text and check it. Checks run in this order,
    /// and the first problem found is the one returned:
    /// 1. the JSON parses (otherwise `Parse`)
    /// 2. the floor has at least one row, and row 0 at least one tile (`EmptyFloor`)
    /// 3. every row is as long as row 0; the first one that isn't is reported (`RaggedFloor`)
    /// 4. then each bot in order: a name already used, exactly (`DuplicateBot`),
    ///    a start outside the floor (`OffFloor`), then the first bad letter in
    ///    its route (`BadMove`). Letters are uppercase only.
    pub fn from_json(text: &str) -> Result<Config, SimError> {
        let config: Config =
            serde_json::from_str(text).map_err(|e| SimError::Parse(e.to_string()))?;
        let width = config.floor.first().map_or(0, |row| row.len());
        if width == 0 {
            return Err(SimError::EmptyFloor);
        }
        if let Some(row) = config.floor.iter().position(|r| r.len() != width) {
            return Err(SimError::RaggedFloor { row });
        }
        let mut seen = HashSet::new();
        for bot in &config.bots {
            if !seen.insert(bot.name.as_str()) {
                return Err(SimError::DuplicateBot(bot.name.clone()));
            }
            let (x, y) = bot.start;
            if x >= width || y >= config.floor.len() {
                return Err(SimError::OffFloor {
                    bot: bot.name.clone(),
                });
            }
            if let Some(step) = bot.route.chars().find(|c| !"NESW".contains(*c)) {
                return Err(SimError::BadMove {
                    bot: bot.name.clone(),
                    step,
                });
            }
        }
        Ok(config)
    }

    /// The floor's width in tiles.
    pub fn width(&self) -> usize {
        self.floor.first().map_or(0, |row| row.len())
    }

    /// The floor's height in tiles.
    pub fn height(&self) -> usize {
        self.floor.len()
    }
}
/// Take one unit of dirt from a tile, if it has any. Returns whether it did.
fn clean(floor: &Mutex<Vec<Vec<u32>>>, (x, y): (usize, usize)) -> bool {
    let mut floor = floor.lock().unwrap();
    let tile = &mut floor[y][x];
    if *tile > 0 {
        *tile -= 1;
        true
    } else {
        false
    }
}

/// One bot's whole shift. Runs on its own thread.
fn walk(plan: BotPlan, floor: Arc<Mutex<Vec<Vec<u32>>>>, width: usize, height: usize) -> BotReport {
    let (mut x, mut y) = plan.start;
    let mut moves = 0;
    let mut bumps = 0;
    clean(&floor, (x, y));
    for step in plan.route.chars() {
        let next = match step {
            'N' if y > 0 => Some((x, y - 1)),
            'S' if y + 1 < height => Some((x, y + 1)),
            'W' if x > 0 => Some((x - 1, y)),
            'E' if x + 1 < width => Some((x + 1, y)),
            _ => None,
        };
        match next {
            Some(tile) => {
                (x, y) = tile;
                moves += 1;
                clean(&floor, tile);
            }
            None => bumps += 1,
        }
    }
    BotReport {
        name: plan.name,
        end: (x, y),
        moves,
        bumps,
    }
}

/// Run the swarm. Each bot gets its own thread, and they all share one floor
/// behind an `Arc<Mutex<..>>`.
///
/// The rules for each bot:
/// - it cleans one unit from its start tile, if there's any dirt there
/// - for each letter of its route it tries to move one tile
/// - a move that would leave the floor is a bump: the bot stays put and cleans nothing
/// - a move that works cleans one unit from the new tile, if there's any dirt there
///
/// Which bot gets the last unit on a tile two bots visit depends on which
/// thread locks first, so the report doesn't say who cleaned what. The totals
/// and the final floor come out the same every time.
pub fn run(config: &Config) -> Report {
    let floor = Arc::new(Mutex::new(config.floor.clone()));
    let (width, height) = (config.width(), config.height());
    let handles: Vec<_> = config
        .bots
        .iter()
        .cloned()
        .map(|plan| {
            let floor = Arc::clone(&floor);
            thread::spawn(move || walk(plan, floor, width, height))
        })
        .collect();
    let mut bots: Vec<BotReport> = handles.into_iter().map(|h| h.join().unwrap()).collect();
    bots.sort_by(|a, b| a.name.cmp(&b.name));

    let floor = floor.lock().unwrap().clone();
    let total = |f: &[Vec<u32>]| f.iter().flatten().sum::<u32>();
    let dirt_left = total(&floor);
    Report {
        bots,
        cleaned: total(&config.floor) - dirt_left,
        dirt_left,
        floor,
    }
}
