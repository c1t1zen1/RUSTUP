Learning goals

By the end of Session 3 a student can:

  1. Define a struct, build one, and give it methods with &self, &mut self and an associated new.
  2. Model a fixed set of choices with an enum, including variants that carry data.
  3. Write an exhaustive match with ranges, _, bindings and guards, and use if let and let ... else.
  4. Choose between Option and Result, and open them with match, unwrap_or, map and ok_or.
  5. Write a custom error enum with Display, and propagate errors with ? and map_err.
  6. Split a crate into modules and control what's visible with pub.

Deeper notes by topic

Structs

Mutability is a property of the binding, not of fields. Students from C# or Java will ask for read-only fields; the Rust answer is private fields plus methods, which comes at the end of the session. #[derive(Debug)] is a macro generating a trait impl; don't go deeper than "it writes the printing code" until Session 4's traits.

Methods and ownership

Hammer the link to Session 2: the receiver is just the first parameter, with the same three ownership choices. A method taking self consumes the value, which is why String::into_bytes(self) leaves the string unusable. Rust has no constructors; new is a naming convention, and clippy's new_without_default lint is why the lab includes a Default impl.

Enums and match

Enums with data are sum types. Show how a C programmer would do it (a tag plus a union, with nothing stopping you reading the wrong field) and how a Python programmer would (a dict with a "type" key). match makes the wrong-field mistake impossible. Arms are checked top to bottom, so a broad pattern before a narrow one triggers an "unreachable pattern" warning; demo it by swapping two arms in the battery example.

Option and Result

Both are ordinary enums in the standard library, with nothing special about them except that the prelude imports them. A good mental model: Option<T> is Result<T, ()> with nicer names. ok_or converts one to the other; .ok() goes back.

The ? operator

? is roughly match x { Ok(v) => v, Err(e) => return Err(From::from(e)) }. The From call is what lets one function mix error types once you implement conversions, which we save for Session 5. For now, students convert explicitly with map_err, which keeps it visible. Clippy's question_mark lint fires on the "before" example: show that live, students love it.

Modules

Draw the module tree, not the file tree. mod robot; declares the module; the file is just where its body lives. crate:: starts from the root, super:: from the parent. Visibility is per item and per field. Skip pub(crate) unless asked.

Lab solution: Robbie's Command Parser

The full file is teacher/s3/lab3-solution-lib.rs; drop it in as labs/lab3-command-parser/src/lib.rs and all nine tests pass, with clippy and fmt clean.

//! Lab 3 reference solution: Robbie's Command Parser.
//! Drop this in as labs/lab3-command-parser/src/lib.rs to check the tests.

/// Which way Robbie is facing. North is up the grid (y grows).
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum Direction {
    North,
    East,
    South,
    West,
}

impl Direction {
    /// Step 2: a quarter turn anticlockwise.
    pub fn turn_left(self) -> Direction {
        match self {
            Direction::North => Direction::West,
            Direction::West => Direction::South,
            Direction::South => Direction::East,
            Direction::East => Direction::North,
        }
    }

    /// Step 2: a quarter turn clockwise.
    pub fn turn_right(self) -> Direction {
        match self {
            Direction::North => Direction::East,
            Direction::East => Direction::South,
            Direction::South => Direction::West,
            Direction::West => Direction::North,
        }
    }
}

/// Everything Robbie understands.
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum Command {
    Forward(u32),
    Left,
    Right,
    Say(String),
    Charge,
    Report,
}

/// Robbie's position, heading and battery.
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct Robot {
    pub x: i32,
    pub y: i32,
    pub facing: Direction,
    pub battery: u32,
}

impl Robot {
    /// Step 1: a fresh Robbie at (0, 0), facing North, battery 100.
    pub fn new() -> Robot {
        Robot {
            x: 0,
            y: 0,
            facing: Direction::North,
            battery: 100,
        }
    }

    /// Step 4: carry out one command and say what happened.
    pub fn apply(&mut self, cmd: Command) -> String {
        match cmd {
            Command::Forward(steps) => {
                if steps > self.battery {
                    return format!("Not enough battery to move {steps}");
                }
                let n = steps as i32;
                match self.facing {
                    Direction::North => self.y += n,
                    Direction::South => self.y -= n,
                    Direction::East => self.x += n,
                    Direction::West => self.x -= n,
                }
                self.battery -= steps;
                format!("Moved {steps}")
            }
            Command::Left => {
                self.facing = self.facing.turn_left();
                format!("Turned left, now facing {:?}", self.facing)
            }
            Command::Right => {
                self.facing = self.facing.turn_right();
                format!("Turned right, now facing {:?}", self.facing)
            }
            Command::Say(text) => format!("Robbie says: {text}"),
            Command::Charge => {
                self.battery = 100;
                String::from("Charged to 100%")
            }
            Command::Report => self.status(),
        }
    }

    /// Step 5: one line about where Robbie is.
    pub fn status(&self) -> String {
        format!(
            "({}, {}) facing {:?}, battery {}%",
            self.x, self.y, self.facing, self.battery
        )
    }
}

impl Default for Robot {
    fn default() -> Self {
        Robot::new()
    }
}

/// Step 3: turn a typed line into a Command, or None if it makes no sense.
pub fn parse(line: &str) -> Option<Command> {
    let line = line.trim();
    let (word, rest) = match line.split_once(' ') {
        Some((w, r)) => (w, r.trim()),
        None => (line, ""),
    };
    match word.to_lowercase().as_str() {
        "forward" => {
            let steps: u32 = rest.parse().ok()?;
            Some(Command::Forward(steps))
        }
        "left" => Some(Command::Left),
        "right" => Some(Command::Right),
        "say" if !rest.is_empty() => Some(Command::Say(rest.to_string())),
        "charge" => Some(Command::Charge),
        "report" => Some(Command::Report),
        _ => None,
    }
}

Things to praise when you walk the room: a match on word.to_lowercase().as_str(); rest.parse().ok()?; a guard like "say" if !rest.is_empty(); checking the battery before moving. Things to gently redirect: an if/else if chain on strings, and .unwrap() on the parsed number (try forward three in cargo run to show why).

Homework 3 solution and grading

Reference files are in teacher/s3/hw3-solution/. Copy lib.rs, parse.rs and robot.rs into a student's src/ to check the tests, or read the key parts here.

pub fn parse_line(line: &str) -> Result<Command, ParseError> {
    let line = line.trim();
    if line.is_empty() {
        return Err(ParseError::Empty);
    }

fn distance(rest: &str) -> Result<u32, ParseError> {
    if rest.is_empty() {
        return Err(ParseError::MissingArgument("distance"));
    }
    rest.parse()
        .map_err(|_| ParseError::BadNumber(rest.to_string()))
}

    /// Carry out one command. Say and Report return a line to print; the rest return None.
    /// A refused move changes nothing.
    pub fn apply(&mut self, cmd: &Command) -> Result<Option<String>, RobotError> {
        match cmd {
            Command::Forward(n) => self.roll(*n, 1).map(|_| None),
            Command::Back(n) => self.roll(*n, -1).map(|_| None),
            Command::Left => {
                self.facing = self.facing.turn_left();
                Ok(None)
            }
            Command::Right => {
                self.facing = self.facing.turn_right();
                Ok(None)
            }
            Command::Say(text) => Ok(Some(format!("Robbie says: {text}"))),
            Command::Charge => {
                self.battery = 100;
                Ok(None)
            }
            Command::Report => Ok(Some(self.status())),
        }
    }

    fn roll(&mut self, n: u32, sign: i32) -> Result<(), RobotError> {
        if n > self.battery {
            return Err(RobotError::LowBattery {
                needed: n,
                left: self.battery,
            });
        }
        let (dx, dy) = self.facing.step();
        let dist = n as i32 * sign;
        let (x, y) = (self.x + dx * dist, self.y + dy * dist);
        if x.abs() > GRID_LIMIT || y.abs() > GRID_LIMIT {
            return Err(RobotError::OutOfBounds { x, y });
        }
        self.x = x;
        self.y = y;
        self.battery -= n;
        Ok(())
    }
/// Run a whole script on a fresh Robbie. Returns where he ended up and everything he said,
/// or the first error, which stops the script.
pub fn run_script(script: &str) -> Result<(Robot, Vec<String>), ScriptError> {
    let mut robbie = Robot::new();
    let mut said = Vec::new();
    for (i, text) in script.lines().enumerate() {
        let line = i + 1;
        let trimmed = text.trim();
        if trimmed.is_empty() || trimmed.starts_with('#') {
            continue;
        }
        let cmd = parse_line(trimmed).map_err(|error| ScriptError::Parse { line, error })?;
        let out = robbie
            .apply(&cmd)
            .map_err(|error| ScriptError::Robot { line, error })?;
        if let Some(out) = out {
            said.push(out);
        }
    }
    Ok((robbie, said))
}

Quiz 3 answer key

#AnswerWhy
1structA struct is AND: every field is there. An enum is OR: exactly one variant.
2fn charge(&mut self)&mut self borrows Robbie mutably. &self can only read, self would use him up, and no self means it isn't a method at all.
3Robot::new("Robbie")No self parameter means it's an associated function, called on the type with ::. A dot is for methods on a value.
4It doesn't compile: Amber isn't coveredmatch must be exhaustive. Missing a variant is error E0004, caught before the program ever runs.
57unwrap_or gives the value inside Some, or the default when it's None. Here it's None, so 7.
6Option<T>Option<T> is Some(value) or None. Rust has no null, so a missing value can't sneak in unannounced.
7Err(...) with a ParseIntErrorparse returns a Result. Text that isn't a number gives Err, and nothing panics unless you unwrap it.
8Returns that Err from the function right away? is the hot potato: Ok gets unwrapped, Err gets returned to the caller immediately.
9No: main returns (), so ? has nowhere to send an error? only works in a function that returns Result or Option. This is error E0277. Make main return Result, or use match.
10Command::Forward(3)A tuple-like variant is built like a function call: Command::Forward(3).
11pubEverything is private by default. pub on the struct doesn't open its fields: each field needs its own pub.
12you only care about one patternif let is a one-armed match. For every variant use match; for looping, while let.
