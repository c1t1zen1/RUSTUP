Learning goals

By the end of Session 6 a student can:

  1. Write a macro_rules! macro with several arms, repetition and recursion, and read a "no rules expected" error.
  2. Name what unsafe unlocks and what it doesn't, and write a // SAFETY: comment that argues each rule.
  3. Wrap a small unsafe core in a safe function, and find the standard library's safe version first.
  4. Call C functions through an unsafe extern "C" block, and pass strings with CStr and CString.
  5. Benchmark honestly: release builds, black_box, best of several runs.
  6. Choose checked_, saturating_ or wrapping_ arithmetic on purpose.
  7. Explain how Rust reaches the browser through WebAssembly, and prepare a crate for cargo publish.
  8. Review code against a rubric and write comments that say what, where and why.

Deeper notes by topic

Macros

Teach a macro as a match on code: the arms are patterns, the fragments (expr, ident, ty, tt) are the bindings. Then say plainly when not to write one: a function or a generic function first, a macro only when you need a variable number of arguments or new syntax. Skip procedural macros beyond one sentence; students have used #[derive] since Session 3, and that's enough to know they exist.

unsafe

The single most important sentence: unsafe doesn't switch any check off. The borrow checker, types and bounds checks all still run. It unlocks five powers (dereferencing raw pointers, calling unsafe functions, implementing unsafe traits, touching mutable statics, reading union fields) and the programmer takes on the proof. Undefined behaviour gets no error message, which is why the SAFETY comment is a rule, not a style point. Rust 2024 also requires unsafe extern and #[unsafe(no_mangle)]; older tutorials online won't have them.

Safe wrappers

Slides 9 and 10 are the pattern the whole standard library uses. Have students find split_at_mut in the std docs and click [src]: it's the same few lines as the slide. Point out that the wrapper's signature carries the proof: the two returned slices borrow from items, so the borrow checker keeps every caller honest.

FFI

Keep it to the C standard library, so nothing needs installing. The C string rule (a 0 byte at the end) is where people get hurt, so spend the time there: CString::new fails if there's a 0 byte inside, and c"..." literals make a &CStr with no allocation. abs(INT_MIN) is the example of a C function whose own rules Rust can't see.

Speed and overflow

The benchmark slide runs on the Playground in debug mode on purpose, so the room sees how misleading that is; then run Lab 6's examples/bench.rs with --release. For overflow, debug builds panic and release builds wrap, which surprises everyone once. The three method families make the intent visible in code.

WebAssembly and publishing

Ten minutes, no live build: the wasm target isn't installed on every machine and the download is large. The Arena is the demo. For publishing, the dry run is the whole lesson; the Lab 6 step 5 test checks the Cargo.toml fields, and nobody publishes for real.

Code review

Read one real Homework 5 submission together (with permission, or your own). Ask the room for comments that say what, where and why, and write them on the board. The Review Lab rubric is the same five headings students will be scored on.

Lab solution: the Final Build Lab

The full file is teacher/s6/lab6-solution-lib.rs; drop it in as labs/lab6-final-build/src/lib.rs, fill the five [package] fields, and all nine tests and seven doc tests pass, with clippy clean and cargo publish --dry-run working.

//! Lab 6: the Final Build Lab.
//!
//! Five small jobs that get Robbie ready to ship: a macro, an unsafe helper
//! with a safe wrapper, two calls into the C library, a stopwatch for
//! benchmarks, and documentation good enough to publish.

use std::ffi::CStr;
use std::time::{Duration, Instant};

/// Step 1. Robbie's beep, as a macro.
///
/// `beep!()` is one beep. `beep!(3)` is three, with spaces between.
/// `beep!(2, "boop")` repeats any word.
///
/// ```
/// use ship_it::beep;
/// assert_eq!(beep!(), "beep");
/// assert_eq!(beep!(3), "beep beep beep");
/// assert_eq!(beep!(2, "boop"), "boop boop");
/// ```
#[macro_export]
macro_rules! beep {
    () => {
        String::from("beep")
    };
    ($n:expr) => {
        $crate::beep!($n, "beep")
    };
    ($n:expr, $word:expr) => {
        vec![$word; $n].join(" ")
    };
}

/// Step 1, part 2. The largest of any number of values, worked out at
/// compile time into a chain of `max` calls.
///
/// ```
/// use ship_it::loudest;
/// assert_eq!(loudest!(3), 3);
/// assert_eq!(loudest!(3, 9, 4), 9);
/// ```
#[macro_export]
macro_rules! loudest {
    ($x:expr) => {
        $x
    };
    ($x:expr, $($rest:expr),+ $(,)?) => {
        std::cmp::max($x, $crate::loudest!($($rest),+))
    };
}

/// Step 2. Splits a slice into two halves you can change at the same time.
/// For an odd length, the extra item goes in the second half.
///
/// The borrow checker won't let you take two `&mut` from one slice, even
/// when they can't overlap, so this uses raw pointers inside `unsafe`.
///
/// ```
/// let mut readings = [1, 2, 3, 4, 5];
/// let (front, back) = ship_it::split_halves(&mut readings);
/// front[0] = 10;
/// back[0] = 30;
/// assert_eq!(readings, [10, 2, 30, 4, 5]);
/// ```
pub fn split_halves(items: &mut [u32]) -> (&mut [u32], &mut [u32]) {
    let len = items.len();
    let mid = len / 2;
    let ptr = items.as_mut_ptr();
    // SAFETY: `ptr` is valid for `len` items because it came from `items`.
    // The first slice covers 0..mid and the second mid..len, so they never
    // overlap, and both live no longer than the `items` borrow they came from.
    unsafe {
        (
            std::slice::from_raw_parts_mut(ptr, mid),
            std::slice::from_raw_parts_mut(ptr.add(mid), len - mid),
        )
    }
}

unsafe extern "C" {
    /// `abs` from the C standard library.
    fn abs(x: i32) -> i32;
    /// `strlen` from the C standard library.
    fn strlen(s: *const std::ffi::c_char) -> usize;
}

/// Step 3. The C library's `abs`, behind a safe Rust function.
///
/// C's `abs(INT_MIN)` is undefined behaviour, so that one input gets `None`
/// instead of ever reaching C.
///
/// ```
/// assert_eq!(ship_it::c_abs(-7), Some(7));
/// assert_eq!(ship_it::c_abs(i32::MIN), None);
/// ```
pub fn c_abs(x: i32) -> Option<i32> {
    if x == i32::MIN {
        return None;
    }
    // SAFETY: abs has no preconditions apart from INT_MIN, ruled out above.
    Some(unsafe { abs(x) })
}

/// Step 3, part 2. The C library's `strlen` on a C string.
///
/// ```
/// assert_eq!(ship_it::c_strlen(c"robbie"), 6);
/// ```
pub fn c_strlen(s: &CStr) -> usize {
    // SAFETY: a &CStr always points at valid memory that ends in a 0 byte,
    // which is exactly what strlen needs.
    unsafe { strlen(s.as_ptr()) }
}

/// Step 4. Runs `job` `runs` times and returns the fastest single run.
/// `runs` of 0 counts as 1. The fastest run is the one least disturbed by
/// whatever else the computer was doing.
///
/// ```
/// let best = ship_it::time_it(3, || {
///     std::hint::black_box(2 + 2);
/// });
/// assert!(best < std::time::Duration::from_secs(1));
/// ```
pub fn time_it<F: FnMut()>(runs: u32, mut job: F) -> Duration {
    let mut best = Duration::MAX;
    for _ in 0..runs.max(1) {
        let start = Instant::now();
        job();
        best = best.min(start.elapsed());
    }
    best
}

/// Counts vowels by walking the `char`s. Given to you for the benchmark.
pub fn vowels_chars(text: &str) -> usize {
    text.chars()
        .filter(|c| matches!(c.to_ascii_lowercase(), 'a' | 'e' | 'i' | 'o' | 'u'))
        .count()
}

/// Counts vowels by walking the bytes. Given to you for the benchmark.
pub fn vowels_bytes(text: &str) -> usize {
    text.bytes()
        .filter(|b| matches!(b.to_ascii_lowercase(), b'a' | b'e' | b'i' | b'o' | b'u'))
        .count()
}

/// Step 5. A one-line status for the crate, read from `Cargo.toml` when it
/// was built: `"ship_it 0.1.0: <description>"`.
///
/// ```
/// assert!(ship_it::status().starts_with("ship_it 0.1.0: "));
/// ```
pub fn status() -> String {
    format!(
        "{} {}: {}",
        env!("CARGO_PKG_NAME"),
        env!("CARGO_PKG_VERSION"),
        env!("CARGO_PKG_DESCRIPTION")
    )
}

The whole answer is about 15 lines in three files. Here is Bot::run with both features:

    pub fn run(&mut self, world: &mut World, cmd: Command) {
        if self.flat {
            return;
        }
        match cmd {
            Command::Forward(n) => {
                for _ in 0..n {
                    if self.battery == 0 {
                        self.flat = true;
                        return;
                    }
                    self.battery -= 1;
                    match self.ahead(world) {
                        Some((nx, ny)) if world.tile(nx, ny) != Some(Tile::Wall) => {
                            self.x = nx;
                            self.y = ny;
                            self.steps += 1;
                            if world.tile(nx, ny) == Some(Tile::Charger) {
                                self.battery = self.capacity;
                            }
                        }
                        _ => {
                            self.bumps += 1;
                            return;
                        }
                    }
                }
            }
            Command::Left => self.facing = self.facing.left(),
            Command::Right => self.facing = self.facing.right(),
            Command::Pick => {
                if world.tile(self.x, self.y) == Some(Tile::Part) {
                    world.set(self.x, self.y, Tile::Floor);
                    self.parts += 1;
                }
            }
            Command::Wait => {}
            Command::Drop => {
                if self.parts > 0 && world.tile(self.x, self.y) == Some(Tile::Floor) {
                    world.set(self.x, self.y, Tile::Part);
                    self.parts -= 1;
                }
            }
        }
    }

Quiz 6 answer key

#AnswerWhy
1Compile error: no rule of squeak! takes an argumentA macro matches what you pass against each arm. The only arm is (), so squeak!(3) has nothing to match and the build stops.
23Each call peels one item off and adds 1: 1 + 1 + 1 + count!() = 1 + 1 + 1 + 0.
3println!("{}", *p); (reading through the pointer)Making a raw pointer and printing it are safe. Reading through it is one of unsafe's five powers, so it's E0133 without unsafe.
4Nothing. It unlocks five extra powers, and you promise you used them correctlyEvery normal check still runs inside unsafe. It only allows things like raw pointer reads and unsafe calls, and the SAFETY comment says why they're fine.
5Rust only sees two &mut borrows of joints at once, not which parts they coverThe borrow checker reasons about joints as a whole. split_at_mut(2) gives both halves safely, because std did the unsafe part once and checked it.
6Write unsafe { abs(-12) }, or declare it as safe fn abs inside the blockRust can't check C code, so calling a foreign function is unsafe unless you mark it safe fn and take on that promise.
7A &str has no 0 byte at the end, so C wouldn't know where it stopsC strings end at a 0 byte. CString (owned) and &CStr (borrowed) guarantee it, and c"robbie" makes a &CStr literal.
8None 255checked_add says None when 250 + 10 won't fit in a u8. saturating_add stops at the top, 255.
9So the optimiser can't work out the answer ahead of time and skip the workIn a release build the compiler may compute a constant answer and delete the loop. black_box hides the value so the work really runs. Time in --release too.
10rustup target add wasm32-unknown-unknownwasm32-unknown-unknown is the browser target. wasm-bindgen (or wasm-pack) then makes the JavaScript glue.
11description and license in Cargo.tomlcrates.io needs description and license (or license-file). repository, keywords and categories help people find it. The Lab 6 step 5 test checks them.
12It calls .unwrap() on the JSON it was givenInput you were handed can be wrong, so a library returns the error instead of panicking. unwrap is fine in tests, not on someone else's data.
