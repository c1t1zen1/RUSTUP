Why Rust?

Fast like C. Safe like a padded room.

  • No garbage collector. Memory is freed at a known point, so performance is predictable.
  • Memory safety checked at compile time. Use-after-free, double free and data races are compile errors in safe Rust.
  • Zero-cost abstractions. Iterators and generics compile down to the loops you'd have written by hand.
  • Great tooling. One tool, cargo, builds, tests, formats, lints and publishes.
Coming from C, C++ or Python

C and C++ trust you completely; Rust checks you. Python checks at runtime and is slower; Rust checks before the program ever runs and compiles to native code.

Real-world anchors students may recognise: Rust is used inside the Linux kernel, Android, Windows components, Firefox, and at Cloudflare, AWS and Discord. Don't oversell; the honest pitch is "the compiler is strict so the program isn't fragile".

The deal

You argue with the compiler now, so you don't argue with your users later.

Rust moves bugs from runtime to compile time.

It will feel strict this week. By week 3 the error messages will feel like a coworker who's always right and never smug about it.

Set expectations: the first week has friction. Reframe compiler errors as free code review. Rust's error messages are famously helpful: they show the exact span, explain why, and often suggest the fix.

Hello, world

fn main and println!

fn main() {
    println!("Hello, Robbie!");
}
  • fn declares a function; main is where every program starts.
  • println! is a macro (the ! gives it away). It checks your format string at compile time.
  • Statements end with ;. Indent with four spaces; cargo fmt does it for you.
Have everyone press Run. If the Playground is slow, that's the network, not Rust. Ask: what happens if you misspell println? The error even suggests the right name.

Variables

Immutable by default

fn main() {
    let battery = 100; // immutable: Robbie's battery label never changes
    let mut distance = 0; // mut: we promise this will change
    distance += 5;
    distance += 3;
    println!("battery {battery}%, drove {distance} m");
}
let battery = 100;
battery = 90; // error[E0384]: cannot assign twice to immutable variable `battery`
Live-demo the E0384 error: remove mut from distance and show the help text "consider making this binding mutable". Immutability by default makes code easier to reason about and helps the compiler optimise.

Constants and shadowing

Same name, new value, maybe new type

const MAX_SPEED_KMH: u32 = 12;

fn main() {
    let reading = "42"; // text from a sensor
    let reading: i32 = reading.parse().unwrap(); // same name, new type
    let reading = reading * 2; // same name, new value
    println!("reading {reading}, top speed {MAX_SPEED_KMH} km/h");
}
  • const needs a type, is SCREAMING_SNAKE_CASE, and is fixed at compile time.
  • Shadowing makes a brand-new variable that hides the old one. It's not mutation, so the type can change.
.unwrap() means "give me the value or crash". It's fine here; Session 3 replaces it with proper error handling. Ask the class: why can't you do the same with let mut? Because mut can change the value but never the type.

usize is the size of a pointer on your machine (64 bits on most laptops) and is what you use to index arrays. Underscores in numbers are just for reading. A char is single quotes, a string is double quotes.

Integer overflow

255 + 10 = ?

fn main() {
    let level: u8 = 250;
    println!("{:?}", level.checked_add(10)); // None: it would overflow
    println!("{}", level.wrapping_add(10)); // 4: wraps around like an odometer
    println!("{}", level.saturating_add(10)); // 255: sticks at the max
}

Plain + that overflows panics in debug builds and wraps in release builds. When overflow is possible, say what you want with checked_, wrapping_ or saturating_.

Contrast with C, where signed overflow is undefined behaviour. Rust never has undefined behaviour in safe code: it either panics or does exactly what you asked.

Compound types

Tuples and arrays

fn main() {
    let pos: (i32, i32) = (3, -2); // a tuple: fixed size, mixed types allowed
    let (x, y) = pos; // destructuring
    let parts = ["head", "chest", "tracks"]; // an array: fixed size, one type
    let zeros = [0; 4]; // four zeros
    println!(
        "x={x} y={y} first={} count={} zeros={zeros:?}",
        parts[0],
        parts.len()
    );
}

Arrays live on the stack and their length is part of their type: [&str; 3]. Reading past the end panics instead of reading random memory. Growable lists (Vec) arrive in Session 4.

Demo: change parts[0] to parts[5]. With a constant index the compiler catches it at compile time; with a runtime index it panics with "index out of bounds". Either way, no buffer overflow.

Functions and expressions

The last line is the answer

fn add_charge(level: u32, charge: u32) -> u32 {
    (level + charge).min(100) // no semicolon: this value is returned
}

fn main() {
    let level = add_charge(70, 45);
    let label = if level == 100 { "full" } else { "charging" };
    println!("{level}% {label}");
}
  • Parameters and return types must be written out. Inside functions, Rust infers the rest.
  • Almost everything is an expression that produces a value: blocks, if, match, even loop.
  • Adding ; turns an expression into a statement, whose value is (), the empty "unit" value.
Classic mistake: writing (level + charge).min(100); with a semicolon, then getting "mismatched types: expected u32, found ()". Show it live. The compiler even suggests removing the semicolon.

Blocks are expressions too

Curly braces hand back a value

fn main() {
    let area = {
        let w = 4;
        let h = 3;
        w * h // the block's value
    };
    println!("the charging pad is {area} square metres");
}

Use this to keep temporary variables out of the way: w and h disappear at the closing brace.

This is the first hint of scope, which matters a lot next session: values are dropped at the end of their block.

Control flow

loop, while, for

fn main() {
    let mut tries = 0;
    let code = loop {
        tries += 1;
        if tries == 3 {
            break tries * 10; // loop can hand back a value
        }
    };
    let mut fuel = 3;
    while fuel > 0 {
        println!("vroom {fuel}");
        fuel -= 1;
    }
    for step in 1..=3 {
        println!("step {step}");
    }
    for part in ["head", "tracks"] {
        println!("oil the {part}");
    }
    println!("door code {code}");
}

1..4 is 1, 2, 3. 1..=4 includes the 4. if conditions must be a real bool: no "truthy" numbers like in C or Python.

Mention loop labels ('outer: loop { break 'outer; }) for nested loops, then move on. For loops over ranges and arrays don't need index variables, which removes a whole class of off-by-one bugs.

Printing

Both run on every graded assignment. Run them before you submit, and your score goes up for free.

The pi example is real: clippy flags hand-typed approximations of PI. It's a nice way to show clippy knows more than syntax. Encourage running cargo fmt on save in their editor (rust-analyzer does this).
