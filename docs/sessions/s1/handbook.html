1. Why Rust

Rust gives you the speed of C and C++ with a compiler that refuses to build programs that would corrupt memory. There's no garbage collector pausing your program, and no "it worked on my machine" segfaults.

The price is that the compiler is picky. Think of it as a very strict, very helpful lab partner: it won't let you hand in the work until it's right, but it always tells you exactly which line is wrong and usually how to fix it.

Remember this

Rust moves bugs left. Picture a timeline: write, compile, run, ship. Rust drags bugs from "ship" all the way left to "compile", where they're cheap to fix and nobody's pager goes off.

cargo new my_app makes a folder with Cargo.toml (the project's ID card) and src/main.rs (where fn main lives). cargo run compiles and runs it. cargo check only checks it, and it's the fastest way to find out whether your code compiles.

Remember this

Check, Run, Release. cargo check while you type, cargo run to try it, cargo build --release when it has to be fast. Debug builds are for you; release builds are for everyone else.

3. Variables: let it be

fn main() {
    let battery = 100; // immutable: Robbie's battery label never changes
    let mut distance = 0; // mut: we promise this will change
    distance += 5;
    distance += 3;
    println!("battery {battery}%, drove {distance} m");
}
Remember this

"Let it be, unless you mut." Every variable is frozen unless you write mut. Rust makes you ask permission to change things, the way a museum makes you ask before touching the exhibits.

Gotcha

Forgetting mut gives error[E0384]: cannot assign twice to immutable variable. The fix is in the error message: "help: consider making this binding mutable". Rust error messages are like a GPS that also tells you why you took the wrong turn.

Constants

const MAX_SPEED_KMH: u32 = 12; needs a type, uses SCREAMING_SNAKE_CASE (because constants are loud and proud), and is fixed when the program compiles.

Shadowing

fn main() {
    let reading = "42";
    let reading: i32 = reading.parse().unwrap();
    let reading = reading * 2;
    println!("{reading}");
}

Each let makes a new variable that hides the old one. Because it's new, its type can change: here from text to a number. mut can't do that.

Remember this

Shadowing is a costume change, mut is a haircut. A costume change can make you a whole different character (a new type). A haircut changes how you look, but you're still the same type of person.

Remember this

i is for "I can go negative". u is for "u can't". The number after it is how many bits you get. And usize is "you size": sized to fit your machine.

Gotcha

Overflow: let x: u8 = 255; x + 1 panics in a debug build and wraps to 0 in release. When it can happen, say what you want: checked_add (gives None), wrapping_add (wraps like a car odometer) or saturating_add (sticks at 255 like a full glass).

Coming from C, C++ or Python

C's int size depends on the platform; Rust's i32 is always 32 bits. Python integers never overflow; Rust's do, but loudly. And Rust never converts between number types silently: let x: f64 = 5; fails, write 5.0 or 5 as f64.

5. Functions and expressions

fn add_charge(level: u32, charge: u32) -> u32 {
    (level + charge).min(100)
}

fn main() {
    println!("{}", add_charge(70, 45));
}

Parameters always have types. The -> u32 says what comes back. The last expression in the body, without a semicolon, is the return value. You can also write return x; to leave early.

Remember this

The semicolon is a mute button. Put one on the last line and the value goes silent, and the function returns (), the empty "nothing" value. Then the compiler complains: "expected u32, found ()". Translation: you muted your answer.

Blocks { }, if, match and loop are all expressions, so they can sit on the right side of =:

fn main() {
    let level = 85;
    let label = if level > 80 { "zoomy" } else { "ok" };
    println!("{label}");
}
Gotcha

Both branches of an if expression must have the same type. if ok { 1 } else { "no" } fails, because Rust has to know the type of the variable before the program runs.

6. Control flow

  • loop { } runs forever until break. It can return a value: break 42;
  • while cond { } runs while the condition is true.
  • for x in 1..=3 { } runs over a range or anything you can iterate. This is the one you'll use most.
Remember this

Two dots stop short, dot-dot-equals goes all the way. 1..4 gives 1, 2, 3. 1..=4 gives 1, 2, 3, 4. The = means "and include the end, please".

Gotcha

if count { } doesn't compile if count is a number. Rust has no "truthy" values. Write if count > 0. Yes, even Python people. Especially Python people.

7. Printing

WriteGet

{:.2}Two decimal places
{:>8} {:<8} {:^8}Right, left, centre in 8 columns
format!(...)Same rules, but gives you a String instead of printing
eprintln!Prints to standard error
Remember this

The question mark asks "what's inside?" {:?} is Debug: it shows you the guts. {} is Display: the nice version for humans.

Cheat sheet

// project
// cargo new app · cargo check · cargo run · cargo build --release
// cargo fmt · cargo clippy -- -D warnings · cargo test

const LIMIT: u32 = 100;          // constant: typed, fixed, LOUD

fn half(n: i32) -> i32 {          // typed params, typed return
    n / 2                         // no semicolon = return value
}

fn main() {
    let a = 5;                    // immutable, i32 by default
    let mut b = 0;                // mutable
    b += a;
    let a = a * 2;                // shadowing: new variable
    let t: (i32, bool) = (1, true);
    let arr = [1, 2, 3];          // [i32; 3]
    let big = if b > 3 { "yes" } else { "no" };
    for i in 0..arr.len() { println!("{i}: {}", arr[i]); }
    for x in arr { println!("{x}"); }   // nicer
    let n = loop { break 7; };
    println!("{a} {b} {:?} {big} {n} {}", t, half(LIMIT as i32));
}

Practice questions

Try each one before opening the answer. The quiz looks a lot like these.

1. Does let x = 5; x = 6; compile?

No: x is immutable. Write let mut x = 5;, or shadow it with let x = 6;.

2. What's the type of let n = 7;?

i32, the default integer type, unless something later forces another type.

3. What does fn f() -> i32 { 5; } do?

It fails to compile: the semicolon makes the body return (), not i32. Remove the semicolon.

4. How many times does for i in 0..3 run?

Three times: 0, 1, 2.

5. What's the difference between {} and {:?}?

{} uses Display (for people). {:?} uses Debug (for programmers) and works on more types, like tuples and arrays.

6. Can shadowing change a variable's type? Can mut?

Shadowing can, because it creates a new variable. mut can't; it only changes the value.

7. What does 200u8.saturating_add(100) give?

255: it stops at the maximum instead of overflowing.

8. Which command is fastest for "does my code compile?"

cargo check. It skips producing a program.

9. Why does if 1 { } fail?

Conditions must be bool. Rust has no truthy numbers.

10. What does let v = loop { break 3; }; set v to?

3. A loop can return the value given to break.
