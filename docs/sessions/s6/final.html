What you build

A crate called robbie_mc with a binary called robbie-mc. The full spec is the project README; the hidden tests check every rule in it. In short:

  • The world is a text map: . floor, # wall, P a spare part. Bad tiles and ragged rows are errors with line and column numbers.
  • Scripts are one command a line: forward, forward N, left, right, pick, wait. Each tile forward costs a battery; bumping a wall still costs it; a bot that tries to move on an empty battery goes flat.
  • Missions are JSON: a map and a list of bots. Mission::prepare checks everything before anything moves and returns the first problem as an McError.
  • Two ways to run: run_mission takes the bots one at a time; run_fleet puts each one on its own thread, sharing the world behind an Arc<Mutex>. The totals must come out the same.
  • A report as text or JSON, from the command line.
$ cargo run -- missions/studio.json
Mission report
  Robbie   at (7, 2) facing E   battery 23  parts 2   steps 7   bumps 0
  Zippy    at (6, 1) facing E   battery 3   parts 1   steps 7   bumps 2
  Dusty    at (8, 4) facing E   battery 0   parts 1   steps 3   bumps 0   FLAT
Parts collected: 4. Parts left: 0.

You can watch that exact mission run in the Robbie Arena, step by step, and paste your own output there to check it matches.

It pulls in everything from the course: enums and match (Session 3), traits and iterators (4), threads, Arc, Mutex and serde (5), and docs, clippy and review (6).

Getting started

git clone https://github.com/c1t1zen1/RUSTUP.git
cd RUSTUP/final/robbie-mc
cargo test            # 12 visible tests, all failing until you fill in the todo!()s
cargo run -- missions/studio.json

Every type, signature and doc comment is already in src/. Every body is a todo!(). A good order is the order the data flows:

  1. world.rs: tiles and map parsing. The visible tests for maps go green first.
  2. command.rs: the script parser.
  3. bot.rs: Facing and Bot::run, the heart of it. Keep it one match on the command.
  4. mission.rs: prepare, run_mission, the report, then run_fleet last.
  5. cli.rs: arguments in, a report or an error out.
Remember this

Write a test before each rule. Every rule in the README is one test in tests/mine.rs: a bump costs a battery, a flat bot ignores pick, a duplicate name is an error. Ten of those and your own-tests points are done.

Grade yourself

The course's grader is in the repo, and it's the same one your teacher runs. From the RUSTUP folder:

cargo run --release --manifest-path grader/Cargo.toml -- check final

Without the hidden tests it scores the visible ones in their place, so every other number is exactly what your teacher will see. It prints a scorecard, lists the lines a reviewer will look at (unwrap, expect, panic!, todo!, unsafe), and writes grade.json. Drop that file on the Review Lab to read each line in plain English, with what to do about it.

Gotcha

A test run that takes over five minutes is stopped. If run_fleet deadlocks, you lose those tests, and you'll be waiting the full five minutes to find out. Lock the world for one command at a time and let go between commands.

Exam day

Exam day is the class after Session 6. It has two parts:

  1. Hand in the project as it stands, with your tests green.
  2. 60 minutes of live coding. You get a one-page handout describing two new features for Robbie Mission Control, and you add them to your own code. The teacher's tests for them join the hidden tests.

We won't say what the features are. We'll say this: they add to the map and to the command language, and they touch Bot::run. A project where each idea lives in one place takes about 15 lines. A project with 'P' and '#' checks scattered through every file takes the whole hour.

Robbie says

Practice for it: pick a new tile and a new command of your own, add them on a branch, and time yourself. If it takes more than three files, that's a design note for your README, and a fix before exam day.

Stretch goals

Pick one, worth up to +5. They only count once the 100 are solid.

  • Robbie Arena in Rust. Build your library to WebAssembly with wasm-pack, expose run_mission_json(&str) -> String, and show it gives the same reports as the Arena.
  • A terminal view. Draw the mission step by step in the terminal with ratatui.
  • Async fleet. A run_fleet_async with tokio tasks instead of threads, giving the same report.

Hand-in checklist

  • No todo!() left, and cargo test is green.
  • At least 10 passing tests of your own in tests/mine.rs, each testing a rule.
  • cargo clippy --all-targets and cargo fmt --check are both clean.
  • No unwrap, expect or panic! on input in src/. Every problem is an McError.
  • A /// comment on every public item, and an example on run_mission.
  • The README says what you added and anything you'd change.
  • The grader runs start to finish on your machine.
