1. Structs

A struct bundles related values under one name, and gives each value a name of its own. You define the shape once, then build as many as you like.

struct Robot {
    name: String,
    battery: u8,
    x: i32,
    y: i32,
}

fn main() {
    // a tuple works, but which number is which?
    let mystery = (87, 3, -2);
    println!("{mystery:?}");

    // a struct says it out loud
    let robbie = Robot {
        name: String::from("Robbie"),
        battery: 87,
        x: 3,
        y: -2,
    };
    println!(
        "{} is at ({}, {}) with {}% battery",
        robbie.name, robbie.x, robbie.y, robbie.battery
    );
}

Fields are read with a dot: robbie.battery. To change a field, the whole binding has to be mut. There's no way to make one field mutable and another not; Rust controls that with privacy instead, which you'll see in section 9.

#[derive(Debug)]
struct Robot {
    name: String,
    battery: u8,
}

fn main() {
    let mut robbie = Robot {
        name: String::from("Robbie"),
        battery: 40,
    };
    robbie.battery += 25; // the whole struct is mut, so every field is
    println!("{robbie:?}");
    println!("{robbie:#?}"); // pretty, one field per line
    println!("{} is at {}%", robbie.name, robbie.battery);
}

#[derive(Debug)] asks the compiler to write the code that prints your struct with {:?}, or {:#?} for one field per line. You'll put derive on nearly every type you write.

Three shortcuts

#[derive(Debug, Clone)]
struct Part {
    name: String,
    rust: u8,
    shiny: bool,
}

#[derive(Debug)]
struct Meters(f64); // a tuple struct: a named wrapper

fn make_part(name: String, rust: u8) -> Part {
    Part {
        name,
        rust,
        shiny: rust == 0,
    } // field init shorthand
}

fn main() {
    let elbow = make_part(String::from("elbow"), 40);
    let knee = Part {
        name: String::from("knee"),
        ..elbow.clone()
    }; // copy the rest
    let reach = Meters(1.2);
    println!("{elbow:?}");
    println!(
        "{} has {}% rust, shiny: {}",
        knee.name, knee.rust, knee.shiny
    );
    println!("reach {} m", reach.0);
}
  • Field init shorthand. If a variable has the same name as the field, write it once: Part { name, rust, .. }.
  • Struct update syntax. ..other copies every field you didn't list. It moves any non-Copy fields out of other, which is why the example clones.
  • Tuple structs. struct Meters(f64); wraps a number so it can't be confused with seconds or kilograms. Read the inside with .0.

2. Methods with impl

An impl block attaches functions to a type. The first parameter decides what the method may do with the value, using exactly the ownership rules from Session 2.

struct Robot {
    name: String,
    battery: u8,
}

impl Robot {
    // an associated function: no self, called as Robot::new
    fn new(name: &str) -> Robot {
        Robot {
            name: name.to_string(),
            battery: 100,
        }
    }

    // &self: look but don't touch
    fn is_tired(&self) -> bool {
        self.battery < 20
    }

    // &mut self: allowed to change fields
    fn work(&mut self, hours: u8) {
        self.battery = self.battery.saturating_sub(hours * 15);
    }
}

fn main() {
    let mut r = Robot::new("Robbie");
    r.work(6);
    println!("{} tired? {} ({}%)", r.name, r.is_tired(), r.battery);
}
First parameterMeaningCalled as
&selfBorrow to readr.is_tired()
&mut selfBorrow to changer.work(6), needs let mut r
selfTake ownership: the value is used upr.into_scrap()

Remember this

&self looks, &mut self touches, self takes. No self at all? Call it on the type with ::.

3. Enums

An enum is a type with a fixed list of possible values, called variants. A Direction can only ever be one of four things, so typos and impossible values simply can't exist.

#[derive(Debug, Clone, Copy, PartialEq)]
enum Direction {
    North,
    East,
    South,
    West,
}

fn opposite(d: Direction) -> Direction {
    match d {
        Direction::North => Direction::South,
        Direction::East => Direction::West,
        Direction::South => Direction::North,
        Direction::West => Direction::East,
    }
}

fn main() {
    let facing = Direction::East;
    println!("{facing:?} turns around to {:?}", opposite(facing));
}

Rust's enums go further than most languages': each variant can carry its own data, of its own shape.

#[derive(Debug)]
enum Command {
    Forward(u32),          // one number
    Turn { degrees: i32 }, // a named field
    Say(String),           // owns some text
    Charge,                // no data at all
}

fn describe(cmd: &Command) -> String {
    match cmd {
        Command::Forward(n) => format!("roll {n} squares"),
        Command::Turn { degrees } => format!("turn {degrees} degrees"),
        Command::Say(text) => format!("say '{text}'"),
        Command::Charge => String::from("plug in"),
    }
}

fn main() {
    let plan = [
        Command::Say(String::from("hi")),
        Command::Forward(3),
        Command::Turn { degrees: -90 },
        Command::Charge,
    ];
    for cmd in &plan {
        println!("{}", describe(cmd));
    }
}

One type, Command, now describes every instruction Robbie understands, and the data each one needs. In other languages you'd reach for a class hierarchy, or a dictionary with a "type" key and a prayer. This is the pattern both the lab and the homework are built on.

Remember this

A struct is a form: it has all of these boxes. An enum is a multiple choice question: it's exactly one of these answers. Structs are AND, enums are OR.

4. match and patterns

match compares a value against patterns, top to bottom, and runs the first arm that fits. It must be exhaustive: every possible value has to land somewhere. This example fails on purpose:

Fails on purpose (E0004). Press Run and read the error.

enum Light {
    Green,
    Amber,
    Red,
}

fn action(light: Light) -> &'static str {
    match light {
        Light::Green => "go",
        Light::Red => "stop",
        // forgot Amber!
    }
}

fn main() {
    println!("{}", action(Light::Amber));
}

That's error E0004, and it's a gift. If you add a variant to an enum next month, the compiler will point at every match that needs updating.

fn mood(battery: u8) -> &'static str {
    match battery {
        0 => "asleep",
        1..=19 => "grumpy",
        20..=79 => "fine",
        80..=99 => "chipper",
        100 => "UNSTOPPABLE",
        _ => "impossible", // u8 goes up to 255, so we still need a catch-all
    }
}

fn weather(rain_mm: u32, windy: bool) -> &'static str {
    match (rain_mm, windy) {
        (0, false) => "lovely",
        (0, true) => "breezy",
        (r, _) if r > 20 => "stay inside, Robbie",
        _ => "drizzly",
    }
}

fn main() {
    for b in [0, 12, 55, 90, 100] {
        println!("{b}% -> {}", mood(b));
    }
    println!("{}", weather(35, false));
}
  • 1..=19 matches a range, inclusive at both ends.
  • a | b matches either pattern.
  • _ matches anything and ignores it. A plain name like r matches anything and keeps it.
  • if after a pattern is a guard: the arm only matches when the condition is true too.
Gotcha

match is an expression, so every arm has to produce the same type. If one arm gives a &str and another a String, that's E0308.

5. if let, let else, while let

When you only care about one pattern, a full match is noisy. Three shorter forms:

fn main() {
    let spare_part: Option<&str> = Some("left knee");

    // if let: only care about one pattern
    if let Some(part) = spare_part {
        println!("Fitting the {part}");
    }

    // let else: get the value or leave early
    let Some(part) = spare_part else {
        println!("No spare. Robbie limps on.");
        return;
    };
    println!("Still holding the {part}");
}
fn main() {
    let mut to_do = vec!["oil knees", "dry antenna", "polish chest"];
    while let Some(job) = to_do.pop() {
        println!("doing: {job}");
    }
}
  • if let runs a block if the pattern matches.
  • let ... else unpacks the value or leaves: the else block must return, break, continue or panic.
  • while let keeps looping as long as the pattern matches. Popping a stack until it's empty is the classic use.

6. Option

Rust has no null. A value that might be missing has the type Option<T>, which is just a standard enum: Some(T) or None. Because it's a different type from T, you can't use it by accident.

fn find_part(name: &str) -> Option<u32> {
    match name {
        "elbow" => Some(12),
        "knee" => Some(7),
        _ => None, // no null: just an honest "nothing"
    }
}

fn main() {
    for name in ["elbow", "antenna"] {
        match find_part(name) {
            Some(shelf) => println!("{name} is on shelf {shelf}"),
            None => println!("no {name} in stock"),
        }
    }
}

Fails on purpose (E0308). Press Run and read the error.

fn find_part(name: &str) -> Option<u32> {
    if name == "elbow" { Some(12) } else { None }
}

fn main() {
    let shelf: u32 = find_part("elbow"); // an Option<u32> is not a u32
    println!("{shelf}");
}

Ways to open the box:

fn find_part(name: &str) -> Option<u32> {
    if name == "elbow" { Some(12) } else { None }
}

fn main() {
    let found = find_part("elbow");
    let missing = find_part("antenna");

    println!("{}", found.unwrap_or(0)); // 12
    println!("{}", missing.unwrap_or(0)); // 0
    println!("{:?}", found.map(|s| s * 10)); // Some(120)
    println!("{}", missing.is_none()); // true

    let shelf = found.expect("the elbow should always be in stock");
    println!("shelf {shelf}");
}
MethodWhat it does
unwrap_or(d)The value, or d if None
map(|v| ...)Change the value inside, if there is one
is_some() / is_none()Just ask
ok_or(err)Turn it into a Result, with err for None
expect("why") / unwrap()The value, or panic
Remember this

Option is a gift box. Some has a present inside, None is empty. You have to open it before you can play.

7. Result and your own errors

Result<T, E> is Ok(T) or Err(E). Use it whenever something can fail and the caller deserves to know why. Parsing is the everyday example:

fn main() {
    for text in ["42", "forty-two", "-3"] {
        match text.parse::<u32>() {
            Ok(n) => println!("{text:>10} -> {n}"),
            Err(e) => println!("{text:>10} -> error: {e}"),
        }
    }
}

For your own code, make the error an enum with one variant per thing that can go wrong, and implement Display so it prints a readable sentence:

use std::fmt;

#[derive(Debug)]
enum ChargeError {
    NoOutlet,
    Overheated { temp: u32 },
}

impl fmt::Display for ChargeError {
    fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
        match self {
            ChargeError::NoOutlet => write!(f, "no outlet in reach"),
            ChargeError::Overheated { temp } => write!(f, "too hot to charge ({temp} C)"),
        }
    }
}

fn charge(temp: u32, outlet: bool) -> Result<u8, ChargeError> {
    if !outlet {
        return Err(ChargeError::NoOutlet);
    }
    if temp > 60 {
        return Err(ChargeError::Overheated { temp });
    }
    Ok(100)
}

fn main() {
    println!("{:?}", charge(30, true));
    match charge(75, true) {
        Ok(level) => println!("charged to {level}"),
        Err(e) => println!("can't: {e}"),
    }
}
Remember this

Option is a shrug. Result is a shrug with an explanation. If the caller would ask "why not?", use Result.

8. The ? operator

Handling every Result with match gets long fast:

fn total_load(a: &str, b: &str) -> Result<u32, std::num::ParseIntError> {
    let x = match a.parse::<u32>() {
        Ok(n) => n,
        Err(e) => return Err(e),
    };
    let y = match b.parse::<u32>() {
        Ok(n) => n,
        Err(e) => return Err(e),
    };
    Ok(x + y)
}

fn main() {
    println!("{:?}", total_load("12", "30"));
    println!("{:?}", total_load("12", "lots"));
}

The ? operator does exactly the same thing in one character. On Ok(v) it gives you v; on Err(e) it returns Err(e) from the whole function, immediately.

use std::num::ParseIntError;

fn total_load(a: &str, b: &str) -> Result<u32, ParseIntError> {
    let x: u32 = a.parse()?; // bad news? return it now. good news? unwrap and carry on
    let y: u32 = b.parse()?;
    Ok(x + y)
}

fn main() {
    println!("{:?}", total_load("12", "30"));
    println!("{:?}", total_load("12", "lots"));
}

It works on Option too, returning None early:

fn first_digit(text: &str) -> Option<u32> {
    let c = text.chars().next()?; // empty text: return None right here
    c.to_digit(10)
}

fn main() {
    println!(
        "{:?} {:?} {:?}",
        first_digit("7 bolts"),
        first_digit("bolts"),
        first_digit("")
    );
}

Two tools make ? fit any situation. map_err turns one error type into yours, and ok_or turns an Option into a Result:

#[derive(Debug)]
enum CmdError {
    BadNumber(String),
}

fn steps(text: &str) -> Result<u32, CmdError> {
    let n = text
        .parse::<u32>()
        .map_err(|_| CmdError::BadNumber(text.to_string()))?;
    Ok(n)
}

fn main() {
    for text in ["4", "four"] {
        match steps(text) {
            Ok(n) => println!("{n} steps"),
            Err(CmdError::BadNumber(bad)) => println!("'{bad}' is not a number"),
        }
    }
}
#[derive(Debug)]
enum FixError {
    NoPart(String),
}

fn find_part(name: &str) -> Option<u32> {
    if name == "knee" { Some(7) } else { None }
}

fn fit(name: &str) -> Result<u32, FixError> {
    let shelf = find_part(name).ok_or(FixError::NoPart(name.to_string()))?;
    Ok(shelf)
}

fn main() {
    for name in ["knee", "visor"] {
        match fit(name) {
            Ok(shelf) => println!("{name}: shelf {shelf}"),
            Err(FixError::NoPart(part)) => println!("{name}: no {part} in stock"),
        }
    }
}

? can only be used inside a function that itself returns Result or Option, otherwise there's nowhere to send the error. This fails on purpose:

Fails on purpose (E0277). Press Run and read the error.

fn main() {
    let n: u32 = "12".parse()?; // main returns (), so where would the error go?
    println!("{n}");
}

The fix for main is fn main() -> Result<(), Box<dyn std::error::Error>> with Ok(()) at the end.

Remember this

? is a hot potato. Good news, you keep it. Bad news, you toss it straight back to whoever called you.

9. Modules and privacy

A module groups code and draws a privacy line around it. Everything is private by default; pub opens it up. use brings a path into scope so you can write the short name.

mod robot {
    pub struct Robot {
        pub name: String,
        battery: u8, // private: only code inside mod robot can touch it
    }

    impl Robot {
        pub fn new(name: &str) -> Robot {
            Robot {
                name: name.to_string(),
                battery: 100,
            }
        }

        pub fn battery(&self) -> u8 {
            self.battery
        }
    }

    pub mod sensors {
        pub fn rain_detected() -> bool {
            true // it's always raining on Robbie
        }
    }
}

use robot::Robot;

fn main() {
    let r = Robot::new("Robbie");
    println!(
        "{} {}% rain={}",
        r.name,
        r.battery(),
        robot::sensors::rain_detected()
    );
}

In a project, mod robot; in src/lib.rs tells Rust to load src/robot.rs. Inside it, use crate::parse::Command; reaches another module from the crate's root. That's exactly how Homework 3 is laid out:

src/
├── main.rs    the program: runs a script and prints what happened
├── lib.rs     pub mod parse; pub mod robot; and run_script
├── parse.rs   Command, ParseError, parse_line
└── robot.rs   Direction, Robot, RobotError

A pub struct doesn't make its fields public. Each field needs its own pub:

Fails on purpose (E0616). Press Run and read the error.

mod robot {
    pub struct Robot {
        pub name: String,
        battery: u8,
    }

    impl Robot {
        pub fn new(name: &str) -> Robot {
            Robot {
                name: name.to_string(),
                battery: 100,
            }
        }
    }
}

fn main() {
    let mut r = robot::Robot::new("Robbie");
    r.battery = 255; // nice try
    println!("{}", r.name);
}

That's what lets a module keep promises, like "the battery never goes over 100". Outside code can only change it through methods the module chooses to offer.

Cheat sheet

struct Robot { name: String, battery: u8 }          // AND: all of these
enum Command { Forward(u32), Say(String), Charge }    // OR: exactly one of these

impl Robot {
    fn new(name: &str) -> Robot { .. }   // Robot::new("x")
    fn look(&self) { .. }                // read
    fn change(&mut self) { .. }          // write
}

match cmd {                              // must cover every case
    Command::Forward(n) if n > 10 => ..,
    Command::Forward(n) => ..,
    Command::Say(text) => ..,
    _ => ..,                             // everything else
}

if let Some(x) = maybe { .. }            // one pattern
let Some(x) = maybe else { return };     // unpack or leave

Option<T>:  Some(v) | None               // maybe nothing
Result<T, E>: Ok(v) | Err(e)             // maybe failed, and why

let n: u32 = text.parse()?;              // Err? return it. Ok? unwrap it.
let n = text.parse::<u32>().map_err(|_| MyError::BadNumber)?;
let shelf = find(name).ok_or(MyError::NotFound)?;

mod robot;            // loads src/robot.rs
pub fn / pub field    // visible outside the module
use crate::robot::Robot;

Practice questions

1. What's the difference between a struct and an enum?

A struct holds all of its fields at once (AND). An enum value is exactly one of its variants (OR).

2. Why does fn charge(&self) { self.battery = 100; } fail?

&self is a shared borrow, which can't change anything. It needs &mut self.

3. How do you call fn new(name: &str) -> Robot defined in impl Robot?

Robot::new("Robbie"). No self means it's called on the type with ::.

4. A match on a u8 covers 0..=100. Why won't it compile?

A u8 goes up to 255. Add a _ arm for 101 to 255.

5. What does Some(4).map(|n| n * 2) give? And None.map(...)?

Some(8), and None. map only touches a value that's there.

6. When would you return Option rather than Result?

When "nothing there" is a normal answer that needs no explanation, like looking something up. Use Result when the caller needs to know what went wrong.

7. What does ? do with Err(e)?

Returns Err(e) from the current function immediately.

8. Your function returns Result<u32, MyError> and text.parse::<u32>()? won't compile. Why, and what's the fix?

The parse error is a ParseIntError, not a MyError. Convert it first: .map_err(|_| MyError::BadNumber)?.

9. What's the difference between unwrap() and expect("...")?

Both panic on None or Err. expect lets you say why it should never happen, which makes the panic message useful.

10. pub struct Robot { battery: u8 } is in mod robot. Can main read r.battery?

No. The struct is public but the field isn't (E0616). Make the field pub or add a pub fn battery(&self) method.
